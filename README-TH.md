# ระบบเช็คอินของแผนก v2.0 (Production-ready)

ระบบนี้เป็นโปรเจกต์ใหม่ แยกจาก “ระบบฟูลของแผนก” โดยสิ้นเชิง

## สิ่งที่ระบบทำได้
- โต๊ะเฉพาะ C11–C60 รวม 50 โต๊ะ
- 3 สถานะเท่านั้น: ว่าง=แดง / ชำระแล้ว=เหลือง / เช็กอินแล้ว=เขียว
- เจ้าหน้าที่หลายเครื่องเห็นข้อมูลเดียวกันแบบ Realtime เมื่อเชื่อม Supabase
- ล็อกอินแยก Admin / Staff
- สแกน QR ของวิทยาลัยจากกล้องมือถือ/แท็บเล็ต
- ถ้า QR ใช้ไม่ได้ ค้นหาด้วยชื่อ / เบอร์โทร / รหัสจอง / เลขโต๊ะ
- เก็บประวัติผู้เช็กอิน เวลา และวิธีเช็กอิน
- Admin นำเข้า CSV รายการ “ชำระแล้ว” จากวิทยาลัย
- ป้องกันโต๊ะนอก C11–C60 ที่ระดับฐานข้อมูลด้วย

## สำคัญมากเรื่อง QR ของวิทยาลัย
ระบบพร้อม “อ่าน QR ของวิทยาลัย” แต่ต้องมีข้อมูลสำหรับจับคู่กับผู้จองก่อน

วิธีที่ชัวร์ที่สุดคือ ใน CSV จากวิทยาลัยให้มีคอลัมน์ `college_qr_value` ซึ่งเก็บค่าที่ได้จาก QR ของผู้จองแต่ละคนแบบตรงตัว เช่น QR สแกนแล้วได้ `ABC123XYZ` ก็ใส่ค่านั้นในแถวของผู้จอง

ระบบยังลองจับคู่กับ `booking_ref` และค่าที่อยู่ใน URL เช่น `booking_id`, `ticket_id`, `id`, `ref`, `code`, `token` ให้ด้วย

จนกว่าเราจะเห็น QR จริงของวิทยาลัย 1 ตัว เรายังไม่สามารถรับประกันรูปแบบการจับคู่ 100% ได้ แต่ไม่ต้องรื้อเว็บใหม่ เมื่อได้ QR จริงเพียงปรับ mapping ให้ตรงกับเว็บวิทยาลัย

## เปิดดูหน้าตาทันที
1. เปิดโฟลเดอร์นี้ใน VS Code
2. เปิด `index.html` ด้วย Live Server
3. ตอนนี้ `config.js` ตั้ง `DEMO_MODE: true` จึงดูและลองระบบได้ทันที

## เปลี่ยนเป็นฐานข้อมูลจริง
### 1) สร้าง Supabase Project
สร้างโปรเจกต์ใหม่สำหรับ “ระบบเช็คอินของแผนก” โดยเฉพาะ ห้ามใช้ฐานเดียวกับระบบฟูลของแผนกถ้าต้องการแยกกัน 100%

### 2) สร้างฐานข้อมูล
ไปที่ Supabase > SQL Editor > New query
คัดลอกทั้งหมดจาก `supabase/schema.sql` แล้ว Run

### 3) สร้างเจ้าหน้าที่
ไปที่ Authentication > Users แล้วสร้าง user ด้วยอีเมล/รหัสผ่าน
จากนั้นคัดลอก UUID ของ user แล้วรันใน SQL Editor เช่น

```sql
insert into public.profiles(id,role)
values ('ใส่-UUID-ตรงนี้','admin');
```

สำหรับเจ้าหน้าที่ทั่วไปใช้ `staff`

### 4) ตั้งค่าเว็บ
ไปที่ Project Settings > API แล้วคัดลอก
- Project URL
- anon public key

เปิด `config.js` แล้วแก้เป็น

```js
SUPABASE_URL: "https://xxxx.supabase.co",
SUPABASE_ANON_KEY: "ค่าของ anon public key",
DEMO_MODE: false,
```

> anon public key ใส่ในหน้าเว็บได้ตามรูปแบบของ Supabase เพราะความปลอดภัยจริงบังคับด้วย RLS ในฐานข้อมูล แต่ห้ามนำ `service_role` key มาใส่เด็ดขาด

### 5) ทดสอบ
เปิดผ่าน Live Server แล้ว Login ด้วยบัญชีที่สร้างไว้

## รูปแบบ CSV
คอลัมน์:
`booking_ref,name,phone,table_number,seats,college_qr_value`

ตัวอย่างมีใน `sample-bookings.csv`

## ก่อนนำไปใช้วันงาน
- ต้องทดสอบ QR จริงจากวิทยาลัยอย่างน้อย 2–3 ใบ
- ต้องทดสอบมือถือ iPhone/Android ที่จะใช้หน้างาน
- เว็บจริงควร deploy ผ่าน HTTPS ไม่เช่นนั้นกล้องบนมือถืออาจไม่อนุญาต
- ให้เจ้าหน้าที่แต่ละคนมีบัญชีของตนเองเพื่อให้ audit log ระบุคนเช็กอินได้
- ควร Export/สำรองรายชื่อก่อนวันงาน

## ความหมายของสถานะโต๊ะ
- แดง “ว่าง” = ไม่มีรายการชำระแล้วจากวิทยาลัยในฐานข้อมูลของแผนก
- เหลือง “ชำระแล้ว” = มีผู้จองจากวิทยาลัยและยังไม่เช็กอิน
- เขียว “เช็กอินแล้ว” = เจ้าหน้าที่แผนกยืนยันเช็กอินแล้ว
